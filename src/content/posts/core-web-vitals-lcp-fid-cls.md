<h2 id="intro">網站使用體驗指標(Web Vitals)計畫</h2>



<p>網站使用體驗指標(Web Vitals)是Google的一項計畫，在2020年五月推出，<strong>目的是提供適用於所有網站的統一指標，讓網站擁有者能夠量化使用者在瀏覽網頁時的體驗</strong>，找出癥結所在，並加以優化。</p>



<p><strong>Google目前將LCP, FID, CLS列為網站使用體驗指標中的三個「核心指標」</strong>，這三個指標分別代表了一個網頁的「載入速度」、「互動性」、「穩定性」。核心指標可能隨著時間的推移或技術的進步在未來有所改變。有核心指標當然就有「一般 」 指標，例如TTFB, FCP, TBT, TTI...等，目前都屬於輔助性的一般指標。</p>



<hr class="wp-block-separator">



<h2 id="web-vitals-and-seo">Web Vitals計畫與SEO的關聯</h2>



<p>SEO和用戶體驗(UX)一直都有密不可分的關係。這並不難理解，Google不希望排在搜尋結果前幾名的網頁帶給使用者不好的體驗。</p>



<p>然而用戶體驗是非常難量化的東西，一般網頁可以做A/B測試來看出哪個版本有較好的用戶體驗，但以搜尋引擎的角度來說要找到這個適用於所有網站的統一指標是相當複雜的。</p>



<p>Chrome Team在經過大量的研究後選定了這三個最具代表性的指標，而Google Search Team也宣布<a href="./seo-newsletter-issue-20.html#toc-1">2021年五月</a>開始將會把這三項指標加入網站的UX評分，成為SEO的排名因素。</p>

<p><strong>根據<a rel="noreferrer noopener" aria-label=" (在新分頁中開啟)" href="https://blog.chromium.org/2020/05/the-science-behind-web-vitals.html#:~:text=Impact" target="_blank">Google的研究</a>，網頁如果能將三項指標都控制在"優良"區間，使用者在頁面加載時離開網頁的機率就會降低24%。</strong>另外，Google建議以75%作為目標，站長們應該讓75%以上的使用者都有優良的體驗。</p>

<h2 id="LCP">什麼是LCP?</h2>



<p>LCP，Largest Contentful Paint或「最大內容繪製」，計算網頁可視區域(viewport)中最大的內容元件載入所需要的時間。換句話說，這項指標標記了頁面上的主要內容被使用者看到所花的時間，相當於網頁給人的第一印象。</p>



<figure class="wp-block-image size-large"><img src="./wp-content/uploads/2020/05/LCP-%E6%9C%80%E5%A4%A7%E5%85%A7%E5%AE%B9%E7%B9%AA%E8%A3%BD-1024x289.png" alt="LCP 最大內容繪製" class="wp-image-1342" loading="lazy" decoding="async" width="1024" height="289"></figure>



<p class="has-yellow-background-color has-background"><strong>標準:</strong> Google為LCP設下的門檻是2.5秒，小於這個數字就算是好的網站體驗。另外，網站至少要讓75%的使用者都達到LCP &lt; 2.5s才算過關。</p>



<h3>LCP例子</h3>



<p>LCP是會改變的，在下圖的CNN例子中，可以看到第一個框架時的LCP是綠色框框裡的"Visual Stories"；在第二~四個框架中，所判定的LCP是標題；然後第五個框架中的LCP是標題下方的圖片。</p>



<p>因為該圖片是最後可視區域上的最大內容元件，因此本頁最後的LCP將以這張圖片載入所需要的時間作為計算。</p>



<figure class="wp-block-image size-large"><img src="./wp-content/uploads/2020/06/LCP%E4%BE%8B%E5%AD%90-CNN-1024x397.png" alt="" class="wp-image-1351" loading="lazy" decoding="async" width="1024" height="397"><figcaption>FCP為First Contentful Paint，代表網頁出現可視元件所需要的時間。在這個例子中，CNN網頁的LCP在第五個frame才載入。</figcaption></figure>



<p>在下圖Instagram的例子中，最大內容元件(IG的logo)在第三個框架就已經載好，網頁的可視區域在載入完畢後並沒有出現更大的元件，因此本頁最後的LCP以logo載入所需要的時間作為計算。</p>



<figure class="wp-block-image size-large"><img src="./wp-content/uploads/2020/06/LCP%E4%BE%8B%E5%AD%90-instagram-1024x397.png" alt="" class="wp-image-1353" loading="lazy" decoding="async" width="1024" height="397"><figcaption>在這個例子中，IG的logo在第三個frame即載入，並保持最大元件一直到其他元件也載入完畢。</figcaption></figure>



<h3>LCP在用戶體驗上的意義</h3>



<p><strong>最大內容繪製(Largest Contentful Paint, LCP)是三項核心指標裡的「速度」代表</strong>。衡量速度的其他指標還有FCP (First Contentful Paint), FMP (First Meaningful Paint), TTFB(Time to First Byte)...等等非常多種，但LCP卻脫穎而出被選為使用體驗核心指標，因為Google在研究後發現最大可視元件的載入速度最能夠影響使用者感知到的網頁載入速度。</p>

<h2 id="FID"> 什麼是FID? </h2>



<p> FID，First Input Delay或「首次輸入延遲時間」，計算使用者第一次與網頁互動(點擊連結、點開下拉選單、填表格...etc)時的延遲時間。這項指標代表了網頁的回應性，在使用者嘗試與網頁互動時是否能馬上回應。</p>



<figure class="wp-block-image size-large"><img src="./wp-content/uploads/2020/05/FID%E9%A6%96%E6%AC%A1%E8%BC%B8%E5%85%A5%E5%BB%B6%E9%81%B2%E6%99%82%E9%96%93-1024x289.png" alt="FID首次輸入延遲時間" class="wp-image-1345" loading="lazy" decoding="async" width="1024" height="289"></figure>



<p class="has-yellow-background-color has-background"><strong>標準:</strong> Google為FID設下的門檻是0.1秒，小於這個數字就算是好的網站體驗。另外，網站至少要讓75%的使用者都達到FID &lt; 2.5s才算過關。</p>



<h3>FID例子</h3>



<p>在載入一個網頁時，瀏覽器會因為主線程(main thread)正在忙碌中而沒辦法即時回應用戶的輸入(user input)，導致使用者可能點了一個按鈕，卻在一些延遲後才出現預期的效果。</p>



<figure class="wp-block-image size-large"><img src="./wp-content/uploads/2020/06/%E9%A6%96%E6%AC%A1%E8%BC%B8%E5%85%A5%E5%BB%B6%E9%81%B2%E6%99%82%E9%96%93%E9%87%8B%E4%BE%8B-1024x462.png" alt="" class="wp-image-1356" loading="lazy" decoding="async" width="1024" height="462"></figure>



<p>在上圖中，使用者在主線程(main thread)忙碌時輸入，就會有延遲時間產生。而FID計算用戶與網頁之間第一次互動的延遲時間。</p>



<p>值得注意的是，使用者如果在兩段黃色區塊間輸入，也就是main thread閒置狀態下輸入，則不會有明顯的延遲(選單點了馬上彈開、鍵盤輸入abc螢幕就馬上跑出abc...)。</p>



<h3>FID在用戶體驗上的意義</h3>



<p><strong>首次輸入延遲時間(First Input Delay, FID)」是三項核心指標裡的「互動性」代表</strong>。衡量互動性的其他指標還有TTI(Time to Interactive), TBT(Total Blocking Time)…等等，但Google最後選擇以FID做為使用體驗的核心指標，因為在研究後發現，第一次的互動延遲最能代表使用者對網頁品質的第一印象，同時互動性的問題也最常發生在網頁尚在載入的時候。</p>

<h2 id="CLS">什麼是CLS?</h2>



<p>CLS，Cumulative Layout Shift或「累計版面配置轉移」，計算了網頁元件在載入時的非預期移位。一個"跳來跳去"的網頁會帶給讀者相當不好的用戶體驗。</p>



<figure class="wp-block-image size-large"><img src="./wp-content/uploads/2020/05/CLS-%E7%B4%AF%E8%A8%88%E7%89%88%E9%9D%A2%E9%85%8D%E7%BD%AE%E8%BD%89%E7%A7%BB-1024x289.png" alt="CLS累計版面配置轉移" class="wp-image-1347" loading="lazy" decoding="async" width="1024" height="289"></figure>



<p class="has-yellow-background-color has-background"><strong>標準:</strong> 網頁元件移位的分數(Layout Shift Score)是一個介於0~1的值，而CLS是所有移位情形的分數加種，因此可能大於1。Google為CLS設下的門檻是0.1，小於這個數字就算是好的網站體驗。另外，網站至少要讓75%的使用者都達到CLS &lt; o.1才算過關。</p>



<h3>CLS例子</h3>



<p>因為網頁上物件載入時間不一，而在閱讀上有跳來跳去的惱人體驗不勝枚舉，像痞客邦所架的部落格幾乎都有這樣的問題。</p>



<figure class="wp-block-video"><video autoplay="" controls="" loop="" poster="./wp-content/uploads/2020/06/layout-instability-poster-1.png" src="https://storage.googleapis.com/web-dev-assets/layout-instability-api/layout-instability2.webm" playsinline="" preload="metadata"></video></figure>



<h3>CLS計算方式</h3>



<p>每一次的元件移位都會有個分數，這個分數的計算是<code>元件移位分數(layout shift score) = 影響範圍(impact fraction) * 移動距離(distance fraction)</code>，以下圖為例，影響的範圍佔了整個畫面(viewport)的75%，元件的移動距離為畫面高度的25%，因此這次移位的分數為0.75*0.25=0.1875。</p>



<figure class="wp-block-image size-large"><img src="./wp-content/uploads/2020/06/CLS-%E8%A8%88%E7%AE%97%E6%96%B9%E6%B3%95-1024x770.png" alt="CLS 計算方法" class="wp-image-1361" loading="lazy" decoding="async" width="1024" height="770"></figure>



<p>累計版面配置轉移(CLS)就是在使用者瀏覽網頁時，每次非預期性的元件移位分數加總。</p>



<h3>CLS在用戶體驗上的意義</h3>



<p><strong>累計版面配置轉移(Cumulative Layout Shift)」是三項核心指標裡的「穩定性」代表</strong>。一個跳來跳去的網頁非常容易惹惱使用者，尤其現在很多網頁瀏覽都發生在速度較不穩定的手機裝置上。</p>

<h3 id="crux">Chrome用戶體驗報告(CrUX Report)</h3>



<p>Chrome用戶體驗報告，Chrome User Experience (CrUX) Report，是一個公開的database，紀錄了每個月Chrome用戶在瀏覽網頁時的網頁表現， 而這項公開資料也開始記錄三項web core vitals。</p>



<p>下圖為台灣104人力銀行網站在2020年四月的web vitals表現，這裡的LCP部分可以這樣解讀: <em>92.08%的使用者在瀏覽104人力銀行網站(www.104.com.tw)時的LCP載入時間是好的(&lt;2500ms)，4.97%普通(&gt;=2500ms, &lt;4000ms)，2.91%不好(&gt;=4000ms)，其中75%的使用者所遇到的LCP小於1.4秒。</em></p>

<h3 id="npm">安裝<code>web-vitals</code>並製作自己的工具</h3>

function sendToGoogleAnalytics({name, delta, id}) {
  // 假設網站已經有一般的GA代碼
  ga('send', 'event', {

<h2 id="final-note">結語</h2>



<p>網站效能(Web Performance)是SEO工作上時常會接觸到的一塊，現在有了Google幫大家選出來的三項標準指標，就可以在和工程師討論時省下一些決定KPIs的功夫。另外Google宣布將把web vitals列為排名因素，想必優化這些項目會成為很多站長們下半年度的目標。</p>
