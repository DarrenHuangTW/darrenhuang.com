<h2 id="toc-1">MFI: Content that only appears in the desktop version will not be indexed</h2>
<p>Due to the epidemic, the full launch of Mobile First Indexing (MFI) has been postponed to March 2021. After its launch,<strong>Content (text, schema, images...) that only appears in the desktop version will be completely ignored</strong>。</p>
<p>Many SEOs believe that Google will give priority to mobile version content after MFI, but recent official statements have stated that content on mobile phones will be the "only" version, and content that only appears on the desktop version will not be included in the index.</p>

<h2 id="toc-3">Will webpages with poor experience affect the SEO performance of other webpages on the same website?</h2>
<p>This is the question John was asked on YouTube,<strong>The questioner's website is a large website. There is a forum on the website. It uses an older CMS. The user experience is poor and difficult to optimize. He is curious.<a href="./core-web-vitals-lcp-fid-cls.html">core web vitals</a>Will forum pages with poor experience drag down the performance of other web pages with good experience?</strong>?</p>
<figure class="embed embed--youtube"><div class="embed__frame"><iframe allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" allowfullscreen="" loading="lazy" referrerpolicy="strict-origin-when-cross-origin" src="https://www.youtube-nocookie.com/embed/JV7egfF29pI?start=848" title="YouTube video player"></iframe></div><figcaption><a href="https://youtu.be/JV7egfF29pI?t=848" rel="noopener noreferrer">View original video on YouTube</a></figcaption></figure>
<p>John's answer is that it depends on whether the website has a clear structure and if Google can understand it, e.g. "<em>All URLs of /forum/ belong to forum pages with poor experience.</em>", then it will not affect other pages; but if the structure is unclear and there is not enough information, Google may need to guess and use the score of the entire website to make the evaluation. At this time, web pages with poor experience may affect pages with good experience.</p>

<h2 id="toc-6">Microsoft launches website analysis tool - Microsoft Clarity</h2>
<p>Microsoft Clarity is similar to Hotjar or FullStory. It is mainly used to analyze the user's experience on the website or check for website bugs. Several noteworthy functions and indicators include:</p>
<ul><li><strong>Heatmaps</strong>: Divided into click maps and scroll maps, you can see how the user interacts with the web page and whether the content is seen.</li><li><strong>Session Playback</strong>: Know which page the user came in from, which page they left out from, how many pages they viewed, how long they stayed...etc., and present it in the form of a video!</li><li><strong>Dead Clicks</strong>: Clicking on the page but no event is triggered means that the user may expect that the components on the page should have an effect after being clicked.</li><li><strong>Rage Clicks</strong>: Clicking the same area quickly in a short period of time means that the components on the web page do not respond as expected after clicking, and the user is unhappy.</li><li><strong>Excessive Scrolling</strong>: On the same page, the number of up and down swipes is greater than expected, which may mean that it is difficult to find web page information. .</li><li><strong>Quick Backs</strong>: Quickly jumping back to the previous page after reaching a new page means that the user may accidentally leave the current page or be dissatisfied with the experience of the new page.</li><li><strong>Price/Restrictions</strong>: Free and no traffic limit!</li></ul>

<h2 id="toc-9">Official video: How Googlebot handles HSTS/307 redirects</h2>
<p>The answer is,<strong>Googlebot ignores HSTS and will still directly use HTTP to request when it sees an HTTP link.</strong>。</p>
<p>HSTS (<em>HTTP Strict Transport Security</em>) is a further protection mechanism for HTTPS, actively informing Chrome that the URL of the website can only be requested using HTTPS. In this way, when the user clicks on an HTTP link, Chrome will automatically convert it to HTTPS. This process is 307.<strong>There are two benefits. First, it saves the time of handshaking with the server during HTTP requests; second, it reduces the risk of being attacked during HTTP requests.</strong>。</p>
