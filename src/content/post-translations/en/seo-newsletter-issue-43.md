<h2 id="toc-1">[SERP Update] Mobile version scroll down to load the next page</h2>
<p>There is a recent change in the SERP of the mobile version that may seem small, but its impact on SEO is worthy of attention. In the search results of the mobile version, when the user slides to the bottom and continues to slide, the next page of results will be loaded. This behavior will continue until the fourth page. Footage can be seen in the Tweet below, which is currently only available in English in the United States.</p>
<blockquote class="embed embed--twitter"><p>Twitter／X Post</p><a href="https://twitter.com/searchliaison/status/1448707950281854982" rel="noopener noreferrer">View original post on Twitter／X</a></blockquote>
<p>said in the official announcement that the reason for this change is that users sometimes want to find enlightening results on the SERP, and these people usually slide to around the fourth page. When I use it myself, I feel that it is less likely to just stop on the first page. Results that are not on the first page are easier to see, because the downward movement is more natural, and there is no extra click action and a pause to feel stuck.</p>
<p>In terms of the impact on SEO, some people think this may<strong>allows webpages ranked slightly lower to have more exposure, while the CTR of websites ranked higher will decrease.</strong>, there is not a lot of research and data on this, but Aleyda Solis has launched one<a href="https://datastudio.google.com/u/0/reporting/8fbf65e6-9c0a-4627-95ac-f858bfac89e2/page/6zXD">Template for Google Data Studio</a>can be observed and deserves attention. Also, John is here<a href="https://twitter.com/JohnMu/status/1450018408796459025?s=20">Twitter</a>said that this is only a change in the UI and should not affect GSC’s ranking and exposure.</p>

<h2 id="toc-2">[News] Bing and Yandex launch “IndexNow” open source protocol</h2>
<p>"IndexNow" is an open source protocol jointly developed by Bing and Yandex. The purpose is to establish a communication method in which websites actively submit content changes to search engines, replacing the inefficient method of active crawling by existing search engines (ex: Google).
The way to submit</p>
<p>is very simple. Just submit (1.) a URL or a list of URLs, and (2.) a key to verify your identity to the dedicated endpoint of the search engine. The search engine that receives the request will then share this information with other search engines that also support this protocol (currently only Bing and Yandex).</p>

<p>digital engine used to<a href="./seo-newsletter-issue-40.html#toc-2">mentioned many times</a>Bing has always advocated this method in indexing. Now it cooperates with Yandex and open source this method. Cloudflare also<a href="https://blog.cloudflare.com/cloudflare-now-supports-indexnow/">announced</a>Even free users can enable the IndexNow function.</p>

<h2 id="toc-9">[Video] Absolute URL vs Relative URL</h2>
<p>In this episode, John answers a basic question, is there a difference between using a relative URL or an absolute URL for internal links? An absolute URL is to use the complete URL in the &lt;a&gt; tag (for example:<code>&lt;a href="https://darrenhuang.com/seo-newsletter-issue-43.html"&gt;</code>), whereas a relative URL uses a partial URL (for example:<code>&lt;a href="/seo-newsletter-issue-43.html"&gt;</code>)。</p>
<p>You may have heard about using absolute URLs when you were learning SEO, but as John said in the video, for search engines, there is no difference between the two when the settings are correct. Relative URLs have their own convenience (for example, when changing domains).</p>

<h2 id="toc-10">[Abstract] Google Search Podcast – Core indicators of website experience</h2>
<p>I found this episode<a href="https://twitter.com/anniesullie">Annie</a>and Vivek are here to chat<a href="./core-web-vitals-lcp-fid-cls.html">Core Web Vitals (CWVs)</a>, Annie is the technical lead in developing CWV, and Vivek is the PM of this project. If you have been paying attention to digital engines, you must be familiar with this topic, but these two are important players in CWV. Some of the things I relayed may not be so impressive, so I still recommend everyone to listen to this episode of the podcast.</p>
<figure class="embed embed--spotify"><iframe allow="autoplay; clipboard-write; encrypted-media; fullscreen; picture-in-picture" loading="lazy" src="https://open.spotify.com/embed/episode/0y4g9xTzpRIXsU55kJseRE" title="Spotify episode"></iframe><figcaption><a href="https://open.spotify.com/episode/0y4g9xTzpRIXsU55kJseRE" rel="noopener noreferrer">View original content on Spotify</a></figcaption></figure>
<p><strong>What is the priority level of CWVs in a company?</strong>Martin said that many companies have not integrated performance into the culture of developing websites. If the website has bugs, it is obvious that they need to be fixed. But if the website is just slow, it is difficult to convince others to regard this as a priority. This is one of the reasons behind the CWVs standard. I hope everyone cares more about the user browsing experience of the web page. The priority depends on the company's emphasis on this. There is no right or wrong, and SEO and ranking are only a small deciding factor.</p>
<p>At about 22;40 seconds, Annie gave a brief introduction<strong>The relationship between SSR, CSR and Hydration</strong>, I recommend you listen or watch this part yourself<a href="https://developers.google.com/web/updates/2019/02/rendering-on-the-web#wrapup">this article</a>. JS Rendering has its benefits and convenience. I think SEOs should not turn on the red light as soon as they hear that a website is made with JavaScript. They should know more about the pros and cons behind it (whether it is for users, performance, or developers), so that communication can be easier.</p>
<p><strong>CWVs future outlook</strong>- CWVs are not a one-time project and will not always be the same three indicators. Annie said that the current three indicators pay more attention to the initial page loading experience, but the user experience should also include the experience after the web page is loaded, such as whether there is any smoothness when scrolling (smoothness), accessibility, privacy, and security. These are their goals. This is<a href="https://www.facebook.com/searchenginecommunity/videos/223574972736913/">Chrome Dev Summit 2020
Mentioned on</a>.</p>
<p><strong>Better Internet Ecosystem</strong>- It is important for every website owner to realize the importance of performance, but to improve the overall network environment requires a more scalable approach, so Vivek mentioned that they are also actively cooperating with CMS platforms, so that a little architectural progress will affect a large number of websites. For example, WordPress launched native lazy loading a few years ago, but it also put lazy-loading on the large hero image. This was actually not good for LCP, so a while ago they worked with the WP development team to solve this problem (there is an article on web.dev<a href="https://web.dev/lcp-lazy-loading/">case analysis</a>is talking about this).</p>
