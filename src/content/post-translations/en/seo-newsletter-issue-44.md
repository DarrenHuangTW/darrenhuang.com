<h2 id="toc-2">[Abstract] Chrome Dev Summit 2021</h2>
<p>The Chrome Developer Conference was held in early November. Although most of it was related to website development, online privacy and security, etc., there were also some things worthy of SEO attention. I would like to share a few key points that I saw.</p>
<p><strong>1. <a href="https://web.dev/lighthouse-user-flows/">Lighthouse new features</a></strong><br/>The current Lighthouse has two major shortcomings. The first is that it can only simulate the cold load performance of the website in a clean environment, and the second is that it does not track the performance of the website after it is loaded. In other words, there is no way to test the performance of the website with a cache or service worker, and to catch the plate displacement phenomenon that occurs when the page scrolls, for example.</p>
<p>The new "User Flows" function is to allow us to see a more comprehensive web page performance when debugging.</p>
<div class="wp-block-image"><figure class="aligncenter size-full is-resized"><img alt="Illustration for SEO e-Newsletter Issue 44 – 2021.11.01~2021.11.15" class="wp-image-3124" decoding="async" height="293" loading="lazy" src="./wp-content/uploads/2021/11/%E6%96%B0%E7%89%88Lighthouse-report.png" width="640"/><figcaption>The new version of Lighthouse tells you the performance of the two stages of "loading" and "scrolling"</figcaption></figure></div>
<p>2. <strong>Two new web experience metrics -<code><a href="https://web.dev/responsiveness/">Responsiveness</a></code>and<code><a href="https://web.dev/smoothness/">Smoothness</a></code><br/></strong><a href="./seo-newsletter-issue-43.html#toc-10">Previous interview</a>Core Web Vital project manager and Tech Lead's podcast mentioned that web page experience indicators will evolve. This event also provided a more in-depth discussion on these two indicators that are under development.<strong>one is<code>Responsiveness</code></strong>, the current FID can only calculate the delay of the first interaction with the web page, but does not consider the execution time of the event and the responsiveness of the web page that is not the first interaction;<strong>the other is<code>Smoothness</code></strong>, everyone should have a similar experience when browsing the web. Some web pages will feel stuck or occasionally freeze when scrolling.<code>Smoothness</code>(Fluency) is used to quantify this bad experience.</p>
<p>in my<a href="./core-web-vitals-lcp-fid-cls.html">Website experience metrics article</a>that there are "core" indicators and of course "general" indicators. These two new indicators are still under development and are currently only general indicators, but they may become core indicators when they mature. (I personally think<code>Responsivess</code>has a high probability of replacing<code>First Input Delay</code>。)</p>
<p>3. <strong><a href="https://developer.chrome.com/blog/auto-dark-theme/">Browser built-in night mode (Dark Mode)</a></strong><br/>Chrome is developing a built-in dark mode in the browser, which uses an algorithm to visually switch the website to a black theme. I think this is very worthy of attention, because it means that after implementation, if the user's device or browser is set to turn on night mode, the UI of the website will not be what you designed.</p>
<p>The company's website has recently undergone a design transformation. I shared this news with the designer and he was quite devastated... Although there is an opt-out method, it is not a good user experience for users who choose night mode to see a website with bright colors.</p>

<h2 id="toc-3">[Controversy] Antitrust charges against AMP project</h2>
<p>AMP has been controversial all the way, but at the end of October 2021, a public formal charging document from 16 states in the United States attracted everyone's attention.<strong>The main complaint of this document is that Google’s underlying purpose of promoting AMP is to encourage websites to adopt the AMP architecture, thereby squeezing out competitors (advertising exchange platforms)</strong>。</p>
<p class="has-bright-red-color has-light-gray-background-color has-text-color has-background"><strong>Note: This prosecution has just been established and has not been concluded.<strong>Google has not received a formal reply so far.</strong>Therefore, this article only summarizes the prosecutor’s views, and the arguments contained therein have not been proven.</strong></p>
<p>This complaint revolves around the technology of how websites make money through advertising. The two current mainstream methods are Header Bidding and Waterfalling. The former is considered to be a method that can bring more advertising revenue to the website, but it requires a piece of JS code to be placed on the website, so AMP pages cannot use Header Bidding. In addition,<strong>The complaint alleges that Google intentionally delays the loading of non-AMP ads by one second.</strong>(Item 249 in the document), to encourage everyone to switch to AMP.</p>
<p>There is also the controversy of Top Stories. Now everyone knows that AMP is no longer a condition for appearing in this placement, but before that, content media websites were somewhat coerced into transforming into AMP because of this large traffic pie placement, and used the Waterfalling advertising model that is more beneficial to Google.</p>

<h2 class="toc-4">[News] Google announces its crawler IP address</h2>
<p>Google recently disclosed the IP address of the crawler source.<a href="https://developers.google.com/search/apis/ipranges/googlebot.json">Googlebot</a>and others<a href="https://www.gstatic.com/ipranges/goog.json">Google Crawlers</a>, the file is in JSON format and will be updated from time to time.</p>
<p>In some special circumstances, the website will need to verify whether the source of the crawl is a search engine (for example, when an opponent sends a robot to crawl website information) to avoid accidentally blocking the search engine request. In the past, the only way was to use reverse DNS lookup to check whether the requested IP was registered in<code>google.com</code>or
Under<code>googlebot.com</code>, to perform the verification action. Now that there is a public IP list, it is much easier for websites with the above needs.</p>
<p>Another convenient thing is that when doing log file analysis, you can also more accurately determine which are the real Googlebot requests. (Note:
The value of<code>user-agent</code>can be set arbitrarily, so it is not trustworthy. )</p>

<h2 id="toc-9">[Video] Timestamp of the video being searched (Key Moments)</h2>
<p>In this video, Danielle explains how Google determines important time periods in videos. Although it is not a new thing, I believe many people are less exposed to it. There are basically two methods.<strong>1.)Leave it to Google to judge:</strong>Make sure the video URL can be crawled + used<code>SeekToAction</code>mark;<strong>2.) <h2 id="toc-10">[Abstract] Google Search Podcast – The Future of SEO</h2>
<p>In this episode, the trio gathers again to discuss the future trends of SEO. There are many topics discussed, so I will pick a few points that I think are interesting to summarize. I recommend listening to them yourself when you have time. If you are usually involved in SEO, the English part should not be too difficult, and Gary’s speeches are very funny and relieve boredom.</p>
<p><strong>Meta Tags</strong>- Meta tags allow webmasters to have some control over website content, so they should not disappear. But Gary said he hopes there won't be more meta tags in the future, as too many will only make it more complicated. He also cited a short story. He and John often jumped out to stop other teams when they wanted to launch new meta tags. For example, if someone wanted to launch a meta tag that allowed webmasters to control whether to allow web content to be automatically translated, they could add a new directive to the meta robots tag. A new meta tag was not required.</p>
<p><strong>Structured Data / Canonical</strong>- Gary said that although Google currently encourages everyone to use structured data and has put a lot of internal resources into developing this area, he feels that at some point in the future, it is likely that even if the web page does not add structured data, Google will be able to understand the content and meaning of the web page almost without error. This is similar to canonical tags. When machine learning advances to the point where the ability to judge original content is very high, most of the time it doesn't matter whether the web page is posted or not. At that time, putting structured data and canonical tags on the web page may just be an act of reaffirming one's stance.</p>
<p><strong>Active or passive crawling and inclusion</strong>- Bing recently promoted<a href="./seo-newsletter-issue-43.html#toc-2">IndexNow</a>allows webmasters to proactively push new or changed web pages to them. Although this method seems to be more efficient, both Gary and Martin remain skeptical, mainly because (1.) this may be unfair to small websites without technical resources, (2.) when this method is scaled up, the search engine side will need a prioritization method, (3.) when opening an external interface, it is difficult to avoid malicious attacks.</p>
<p><strong>machine production content
Contents produced by</strong> - <a href="./seo-newsletter-issue-38.html#toc-2">machine</a>is a big topic. They have seen the very high-quality content produced by the machine. Gary believes that their current position is mainly,<strong>If the content produced by the machine has not been reviewed by humans, then Google does not want to appear in the search results.</strong>; If someone reviews it before putting it online, it doesn't matter.</p>
