<h2 id="intro">Website experience indicator (Web Vitals) plan</h2>
<p>Website experience indicators (Web Vitals) are a project of Google, launched in May 2020.
The purpose of<strong>is to provide unified metrics for all websites, allowing website owners to quantify the user experience when browsing the web.</strong>, find out the crux and optimize it.</p>
<p><strong>Google currently lists LCP, FID, and CLS as three "core indicators" in website experience indicators.</strong>, these three indicators represent the "loading speed", "interactivity" and "stability" of a web page respectively. Core metrics may change in the future over time or as technology advances. There are of course core indicators and "general" indicators, such as TTFB, FCP, TBT, TTI... etc., which are currently auxiliary general indicators.</p>
<hr class="wp-block-separator"/>
<h2 id="web-vitals-and-seo">The relationship between the Web Vitals project and SEO</h2>
<p>SEO and user experience (UX) have always been inseparable. This is not difficult to understand. Google does not want the web pages ranked at the top of the search results to give users a bad experience.</p>
<p>However, user experience is very difficult to quantify. Generally, web pages can be tested through A/B testing to see which version has a better user experience. However, from a search engine perspective, it is quite complicated to find this unified indicator that applies to all websites.</p>
<p>Chrome Team selected these three most representative indicators after extensive research, and Google Search Team also announced<a href="./seo-newsletter-issue-20.html#toc-1">May 2021</a>will initially add these three indicators to the website’s UX score and become SEO ranking factors.</p>

<h2 id="LCP">What is LCP?</h2>
<p>LCP, Largest Contentful Paint or "Maximum Content Drawing", calculates the time required to load the largest content element in the viewport of a web page. In other words, this indicator marks the time it takes for users to see the main content on the page, which is equivalent to the first impression of the web page.</p>
<figure class="wp-block-image size-large"><img alt="LCP maximum content drawing" class="wp-image-1342" decoding="async" height="289" loading="lazy" src="./wp-content/uploads/2020/05/LCP-%E6%9C%80%E5%A4%A7%E5%85%A7%E5%AE%B9%E7%B9%AA%E8%A3%BD-1024x289.png" width="1024"/></figure>
<p class="has-yellow-background-color has-background"><strong>standard:</strong>The threshold set by Google for LCP is 2.5 seconds. Less than this number is considered a good website experience. In addition, the website must have at least 75% of users reaching LCP &lt; 2.5s to pass.</p>
<h3>LCP example</h3>
<p>LCP will change. In the CNN example below, you can see that the LCP in the first frame is "Visual Stories" in the green frame; in the second to fourth frames, the determined LCP is the title; and then the LCP in the fifth frame is the picture below the title.</p>
<p>Because this picture is the largest content element in the last visible area, the final LCP of this page will be calculated based on the time it takes to load this picture.</p>

<h3>LCP in user experience</h3>
<p><strong>Largest Contentful Paint (LCP) is the representative of "speed" among the three core indicators</strong>. There are many other indicators to measure speed, such as FCP (First Contentful Paint), FMP (First Meaningful Paint), TTFB (Time to First Byte), etc., but LCP stood out and was selected as the core indicator of user experience because Google found after research that the loading speed of the largest visual component can most affect the user's perceived loading speed of a web page.</p>

<h2 id="FID">What is FID?</h2>
<p>FID, First Input Delay or "First Input Delay", calculates the delay time when the user first interacts with the web page (clicking on a link, clicking on a drop-down menu, filling in a form...etc). This metric represents the responsiveness of a page, indicating whether it responds immediately when a user attempts to interact with the page.</p>
<figure class="wp-block-image size-large"><img alt="FID first input delay time" class="wp-image-1345" decoding="async" height="289" loading="lazy" src="./wp-content/uploads/2020/05/FID%E9%A6%96%E6%AC%A1%E8%BC%B8%E5%85%A5%E5%BB%B6%E9%81%B2%E6%99%82%E9%96%93-1024x289.png" width="1024"/></figure>
<p class="has-yellow-background-color has-background"><strong>standard:</strong>The threshold set by Google for FID is 0.1 seconds. Less than this number is considered a good website experience. In addition, the website must have at least 75% of users reach FID &lt; 2.5s to pass.</p>
<h3>FID example</h3>
<p>When loading a web page, the browser will not be able to respond to user input immediately because the main thread is busy. As a result, the user may click a button, but the expected effect will appear after some delay.</p>
<figure class="wp-block-image size-large"><img alt="Illustration for Three core indicators of website experience - LCP, FID, CLS" class="wp-image-1356" decoding="async" height="462" loading="lazy" src="./wp-content/uploads/2020/06/%E9%A6%96%E6%AC%A1%E8%BC%B8%E5%85%A5%E5%BB%B6%E9%81%B2%E6%99%82%E9%96%93%E9%87%8B%E4%BE%8B-1024x462.png" width="1024"/></figure>
<p>In the above figure, if the user inputs when the main thread is busy, there will be a delay time. FID calculates the delay between the user's first interaction with the web page.</p>
<p>It is worth noting that if the user inputs between the two yellow blocks, that is, inputting when the main thread is idle, there will be no obvious delay (the menu pops up immediately when clicked, and the screen immediately exits abc when the keyboard enters abc...).

<h3>FID in user experience</h3>
<p><strong>"First Input Delay (FID)" is the representative of "interactivity" among the three core indicators</strong>. Other indicators for measuring interactivity include TTI (Time to Interactive), TBT (Total Blocking Time), etc., but Google finally chose FID as the core indicator of user experience because after research, it was found that the first interaction delay best represents the user's first impression of the quality of the web page, and interactivity problems most often occur when the web page is still loading.</p>

<h2 id="CLS">What is CLS?</h2>
<p>CLS, Cumulative Layout Shift, or "Cumulative Layout Shift," accounts for the unexpected shifting of web page elements during loading. A webpage that "jumps around" will give readers a very bad user experience.</p>
<figure class="wp-block-image size-large"><img alt="CLS cumulative layout configuration transfer" class="wp-image-1347" decoding="async" height="289" loading="lazy" src="./wp-content/uploads/2020/05/CLS-%E7%B4%AF%E8%A8%88%E7%89%88%E9%9D%A2%E9%85%8D%E7%BD%AE%E8%BD%89%E7%A7%BB-1024x289.png" width="1024"/></figure>
<p class="has-yellow-background-color has-background"><strong>standard:</strong>The layout shift score of web page elements is a value between 0 and 1, and CLS is the score addition of all shift situations, so it may be greater than 1. The threshold set by Google for CLS is 0.1. If it is less than this number, it is considered a good website experience. In addition, the website must have at least 75% of users reaching CLS &lt; o.1 to pass.</p>
<h3>CLS example</h3>
<p>Because the loading time of objects on the web page is different, and the annoying experience of jumping around while reading is numerous, almost all blogs like Pixnet have this problem.</p>

<h3>CLS calculation method</h3>
<p>Each component shift will have a score. The calculation of this score is<code>元件移位分數(layout shift score) = 影響範圍(impact fraction) * 移動距離(distance fraction)</code>, take the following figure as an example. The affected range accounts for 75% of the entire screen (viewport). The moving distance of the component is 25% of the screen height. Therefore, the shift score this time is 0.75*0.25=0.1875.</p>
<figure class="wp-block-image size-large"><img alt="CLS calculation method" class="wp-image-1361" decoding="async" height="770" loading="lazy" src="./wp-content/uploads/2020/06/CLS-%E8%A8%88%E7%AE%97%E6%96%B9%E6%B3%95-1024x770.png" width="1024"/></figure>
<p>Cumulative Layout Shift (CLS) is the sum of the scores of unexpected component shifts every time a user browses a web page.

<h3>CLS in user experience</h3>
<p><strong>Cumulative Layout Shift" is the representative of "stability" among the three core indicators</strong>. A web page that bounces around can easily annoy users, especially now that many web browsing occurs on mobile devices with unstable speeds.</p>

<h2 id="tools">Web Vitals Measurement/Monitoring Tool</h2>
