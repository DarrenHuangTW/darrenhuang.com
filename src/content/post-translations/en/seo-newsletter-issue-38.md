<h2 id="toc-10">[Abstract] Google Search Podcast – Web Worker &amp; Universal Search</h2>
<p>Gary continues<a href="./seo-newsletter-issue-36.html#toc-10">first few episodes</a>For topics, Google first extends the words entered by the user into a parsed query, then sends it to the index database, pulls out relevant results, and sorts each result with a score. But there is more than one index library. In addition to ordinary web pages, there are also different index libraries for pictures, videos, news, etc. Each index library will receive this parsed query and return its results.</p>
<p>Although each index library returns a result, not all SERPs have pictures or videos. This is actually because there is a mechanism at the top, let's call it "Universal Mixer", which is responsible for piecing together what elements should be in the final search results. This most commonly used search function is called Universal Search, which not only sorts web pages, but also includes other results such as pictures or videos.</p>
<p>The way Universal Mixer selects which elements appear is like a bidding system. For example<em>feature snippet</em>Say it has a score of 1,000 and wants to compete for the first place position, while<em>Web page index</em>It also said that it had a result with a score of 1,500 and wanted to compete for the first place. The result was that the final SERP first place was taken by this web page result without a feature snippet.</p>
<p>Next, the user's behavior will also affect the judgment of Universal Mixer. For example, if many people search for a certain search term and then go to the "image search" results, then Google will learn that this search term may need to include an image field in the results of Universal Search.</p>
<p>John summed it up well, saying that Universal Mixer is actually like a search engine for search engines (web, image, news...etc)!</p>

<p>Front-end engineers or those who are more exposed to technical SEO may have heard of the technology of Web Worker or Service Worker. In this podcast, Martin first explains what it is and how it affects SEO. I have always liked listening to Martin talk about technical things. Although I had done a little research before, it was only after listening to his explanation that I felt enlightened. The following is my understanding. I recommend that everyone who is interested can listen to it for themselves. If there is anything wrong with the explanation, please help to prove it!</p>
<p>Service Worker is a type of Web Worker. Generally speaking, JS will use the main thread, and this technology allows you to execute code on other execution threads. In other words, usually when you click a button on a web page and then start running JS behind the scenes, your main thread is blocked until the JS is finished running, and there is no way to perform other events. However, web workers can allow the code to be executed in a separate environment, allowing the main thread to perform other actions.</p>
<p>Another biggest benefit of Web Worker is that it can execute code directly locally without going through the server. For example<a href="https://squoosh.app/">Squoosh.app</a>This image compression website compresses and converts images in your browser (local) instead of uploading images to the server, converting/compressing them, and then downloading them back.</p>
<p>The most commonly heard service worker application for SEOs may be PWA, which turns your website into an "APP" that can be installed. You can also run content when offline, send out push notifications... and so on. (Speaking of digital engines<a href="./">main website</a>It is PWA+AMP, and the above functions will also be available when browsing on mobile phones).</p>
<p>These relatively trendy technologies are more related to UX. Martin said that most applications will not affect Googlebot's crawling and indexing, but sometimes engineers are too creative and do some weird things that may still affect SEO. For example, the main thread only loads the template of the web page, letting the service worker load the content behind the scenes, and then pushes it to the main thread after completion. This may cause Googlebot to make judgments in the rendering phase without waiting for the service worker to complete the work.<a href="https://twitter.com/g33konaut/status/1134013632931667968">The web page is rendered but no content is seen.</a>。</p>
