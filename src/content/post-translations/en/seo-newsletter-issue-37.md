<h2 id="toc-4">Gary: Keep the redirection active for at least a year before removing it.</h2>
<p>Of course, it would be best if you can never take it off.</p>
<p>In most cases, it is recommended not to remove it after redirecting it, because (1.) users may still visit the old URL accidentally, and you want them to see the correct web page, and (2.) you hope that the SEO value collected by the old URL can be transferred to the new URL.</p>
<p>Gary's answer is that, aside from (1.), the official recommendation is to maintain the redirection for at least one year to ensure that Google has enough time to transfer all signals to the new URL.</p>

<h2 id="toc-6">Tip: Simulate user behavior to debug CLS issues</h2>
<p>"When using PageSpeed ​​Insights, it says that the website's CLS is fine, but the Search Console shows that the CLS score is extremely poor. Why is there such a difference?"</p>
<p><a href="./core-web-vitals-lcp-fid-cls.html#CLS">Cumulative layout transfer</a>(CLS, Cumulative Layout Shift) is a difficult indicator to debug because<strong>It measures more than just unexpected tectonic movements of a page as it loads</strong>, also includes the user's movements while browsing the website. When using tools such as PageSpeed ​​Insights, because the tool does not interact with the website (ex: scrolling, waiting for more than a certain period of time), some section movements will not be detected by the laboratory tool, resulting in such a gap.</p>
<p>Rick Viscomi wrote an article. In addition to explaining the above reasons, he also provided two solutions, (1.) Use<a href="https://chrome.google.com/webstore/detail/web-vitals/ahfhijdlegdabablpippeagghigmibma?hl=en">browser plug-in</a>, and actually interact with the web page, or (2.) use the Inject Script function in WebPageTest to force the tool to scroll down after the web page is loaded, and then determine whether there is a CLS problem.</p>
<div class="wp-block-image"><figure class="aligncenter size-full is-resized"><img alt="Illustration for SEO e-Newsletter Issue 37 – 2021.07.16~2021.07.31" class="wp-image-2882" decoding="async" height="261" loading="lazy" src="./wp-content/uploads/2021/07/rhot7.jpg" width="638"/><figcaption>In the picture, you can see that the screen does not stop at the top, but scrolls down to reflect the shifting of the sections.</figcaption></figure></div>
<p>I think the second method is very clever. Inserting additional scripts is also a function of PageSpeedTest that I didn’t know before. I recommend it to everyone!</p>
<p>link:<a href="https://dev.to/rick_viscomi/simulating-real-users-in-the-lab-to-debug-cls-issues-3hnp">Article by Rick Viscomi</a></p>

<h2 id="toc-7">Image search command<code>src:</code> &amp; <code>imagesize:</code></h2>
<p>Google updated its
Documentation for the<a href="https://developers.google.com/search/docs/advanced/debug/search-operators/overview">search command</a>, Introduction<code>src:</code>and<code>imagesize:</code>These are two rare commands specific to image search.</p>
<p>among them<code><strong>src:</strong></code>can return "images from a specific domain". A very practical method is to know which other websites your images are referenced by. For example, enter<code><em>-site:darrenhuang.com src:darrenhuang.com</em></code>You can see which web pages have my pictures embedded in them. Of course, this is limited to the situation where the other party directly uses your image URL. If the image is downloaded and then re-uploaded, it will be invalid.</p>
<div class="wp-block-image"><figure class="aligncenter size-large is-resized"><img alt="Illustration for SEO e-Newsletter Issue 37 – 2021.07.16~2021.07.31" class="wp-image-2874" decoding="async" height="271" loading="lazy" src="./wp-content/uploads/2021/07/%E5%9C%96%E7%89%87%E6%90%9C%E5%B0%8Bsrc%E6%8C%87%E4%BB%A4-1024x462.png" width="600"/><figcaption>Know which web pages use images from darrenhuang.com</figcaption></figure></div>
<p>another
This is the first time I know the<code><strong>imagesize:</strong></code>command. Its function is to find pictures of a specific size. For example, enter<code><em>tokyo olympics imagesize:900X1200</em></code>You can see the Tokyo Olympics picture with a length of 1200px/width of 900px.</p>
<p>According to the test, the numerical part must be accurate. If it is a little different, different results will be obtained. In addition, this command cannot find pictures based on "proportion". This is a function that I think may be more useful.</p>

<h2 id="toc-10">[Video] Will using a shared server be bad for SEO?</h2>
<figure class="embed embed--youtube"><div class="embed__frame"><iframe allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" allowfullscreen="" loading="lazy" referrerpolicy="strict-origin-when-cross-origin" src="https://www.youtube-nocookie.com/embed/VQpRU8aqSZk" title="YouTube video player"></iframe></div><figcaption><a href="https://www.youtube.com/watch?v=VQpRU8aqSZk" rel="noopener noreferrer">View original video on YouTube</a></figcaption></figure>
<p>This video episode answers a very common myth - "<em>Sharing the server with other websites (shared hosting) will result in poor SEO performance of the website?</em>", the answer simply is<strong>No</strong>, but there are usually two reasons behind such concerns:</p>
<p><strong>1.) The person sharing the server with me may be a bad website. I am afraid that if he is punished, I will be punished too!<br/></strong>No, sharing servers or sharing IP addresses is a natural thing in the online world. Google looks at the website, not your "neighbors".<a href="https://www.searchenginejournal.com/google-multiple-sites-ip-not-problem-similar-content/254799/#:~:text=all%20the%20same%20ip%20address%20%E2%80%94%20that%E2%80%99s%20really%20not%20a%20problem%20for%20us.%20it%E2%80%99s%20really%20common%20for%20sites%20to%20be%20on%20the%20same%20ip%20address.%20that%E2%80%99s%20kind%20of%20the%20way%20the%20internet%20works.">This is not the first time John has answered this question</a>。</p>
<p><strong>2.) Shared servers may cause unstable server performance. My website will be overloaded because the neighbors are too popular!<br/></strong>This does cause problems, but shared servers can be very stable; dedicated servers can also be terrible. Although dedicated servers are generally better than shared servers, stability and performance still depend on the provider and should not be generalized. My suggestion is that small and medium-sized websites should consider VPS (shared physical server, non-shared server resources).</p>
