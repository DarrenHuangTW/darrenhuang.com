<h2 id="toc-2">[News] New robots tag:<code>indexifembedded</code></h2>
<p>Google will support a new tag starting in January 2022:<code>indexifembedded</code>, this parameter can be used in meta robots tag or X-Robots-Tag. New tags allow a file to be<code>noindex</code>You can get additional control when you use it. In other words, when a file (whether text, image, or PDF...) has the following instructions, the file itself will not be indexed, but if it is "embedded" on other web pages (such as<code>iframe</code>), the above content will be indexed.</p>
<pre class="wp-block-preformatted">// HTML
&lt;meta name="googlebot" content="noindex,indexifembedded" /&gt;

// HTTP Header
X-Robots-Tag: googlebot:noindex,indexifembedded</pre>
<p>A few years ago, there was a case where a website replaced all images with Instagram. As a result, it lost a lot of image search traffic. The reason was that IG placed all the imported resources.<code>noimageindex</code>label. Therefore, if you want to insert resources later, you might as well check whether there is a noindex tag in it.</p>

<h2 id="toc-4">[Discussion] SEO practices for website paywall content</h2>
<p>Nowadays, many news or content websites place articles behind paywalls or subscription walls. However, how do we enable search engines to crawl and include the complete content so that ordinary users must pay (or register) to see the articles, while avoiding being judged as "cloaking"? Many SEO personnel do not know the details.</p>
<p>Most recent<a href="https://twitter.com/antoineripret/status/1483813748821405700">Twitter thread</a>discusses current general industry practices, as well<a href="https://developers.google.com/search/docs/advanced/structured-data/paywalled-content">Suggested by Google
The method of</a>is highly recommended for everyone to read. To put it simply, the server determines whether the request comes from a search engine or a real person, returns different files, and uses them in the structured data part.<code>isAccessibleForFree</code>attribute to tell which part is paywall content; in addition, you can add<code>noarchive</code>meta robots tag prevents content from being stored in cache.</p>
<p>Finally, a little trick is that ordinary users can use<a href="https://search.google.com/test/rich-results">structured data testing tool</a>is used to run web pages with paywalls. Since the tool’s request comes from a search engine, there is a high chance that you can see blocked content in the source code of its results!</p>

<h2 id="toc-5">[Interesting Fact] Shopify page title is added (1)</h2>
<p>An interesting case happened a while ago. A large number of Shopify webpage titles were preceded by a<code>(1)</code>, after some digging, I found out that it was a chatbot on the webpage. When the webpage was loading, a message would pop up to say hello, and (1) meant that there was a new message.</p>
<p>It is very common for scripts on web pages to rewrite titles. If you have ever visited a phishing website, you should have seen the title of the web page flashing around at the top of the browser to attract attention. But this time it was a small tragedy because the chatbot triggered the title rewriting script when the web page was loaded (rather than after some interaction), and did not determine whether the other party was a search engine or a user.</p>

<h2 id="toc-9">[Video] Does changing the URL structure affect SEO?</h2>
<figure class="embed embed--youtube"><div class="embed__frame"><iframe allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" allowfullscreen="" loading="lazy" referrerpolicy="strict-origin-when-cross-origin" src="https://www.youtube-nocookie.com/embed/FHjVmi1tkEw" title="YouTube video player"></iframe></div><figcaption><a href="https://www.youtube.com/watch?v=FHjVmi1tkEw" rel="noopener noreferrer">View original video on YouTube</a></figcaption></figure>
<p>The theme of this film is relatively basic, but it has many important concepts. Google's index database is a very large database based on URLs. Therefore, whenever the URL is changed (as large as changing the domain, as small as removing the slash at the end of the URL), the original data must be transferred to the new URL.</p>
<p>Several suggestions include: (1.) Do your homework; (2.) Create a comparison table (URL Mapping) of the old and new web pages; (3.) Execute - use 301 redirects, update links, sitemaps, structured data on the website, etc.; (4.) Monitor the transfer process. Usually important web pages will be processed faster, but it may take more than a few months to fully reflect.</p>
