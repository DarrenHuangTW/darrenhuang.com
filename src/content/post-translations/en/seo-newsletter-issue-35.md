<h2 id="toc-1">The number of FAQ information on each page of search results has been reduced to two.</h2>
<p>"FAQ" and "How-To" are in<a href="./google-io-2019-seo-news-information.html#new-fs">unveiled in 2019

<h2 id="toc-9">official new document - redirection and Google search</h2>
<p>The main purpose of redirection is to let users and Google know what the new destination URL is when the URL changes. Although it usually has no impact on users, there are two main types of redirects for Google - permanent redirect and temporary redirect.</p>
<p>Regardless of permanent or temporary redirection, there are many ways to achieve it, including the familiar 301 and 302; JS redirect; meta refresh; and the ones that have caused heated discussions abroad.<code>Crypto Redirect</code>. This new term sounds cool, but it actually just refers to putting a message on the original web page and a normal hyperlink to the new web page, which is more or less like this: 😂</p>

<h2 id="toc-10">[Abstract] Google Search Podcast – Google I/O &amp; Information Search</h2>
<figure class="embed embed--spotify"><iframe allow="autoplay; clipboard-write; encrypted-media; fullscreen; picture-in-picture" loading="lazy" src="https://open.spotify.com/embed/episode/3ttE5qbxVrbLtMp8Wy7vKT" title="Spotify episode"></iframe><figcaption><a href="https://open.spotify.com/episode/3ttE5qbxVrbLtMp8Wy7vKT" rel="noopener noreferrer">View original content on Spotify</a></figcaption></figure>
<p><strong>Google IO 2021</strong><br/>Martin said that he doesn't think there is a need for more search-related speeches at developer conferences like Google I/O, because compared to things like Google Cloud or Tensorflow, which have a direct impact on developers, if Google does a good job in search, developers actually have nothing to worry about.</p>
<p>Gary added that there have always been two groups of voices in Google. One group prefers not to disclose the details of search to the outside world, because ideally Google can perfectly understand a web page or website, and webmasters do not need to do anything special to technically "optimize" SEO; while the other group acknowledges Google's shortcomings in search and communicates externally so that SEOs know how to help Googlebot understand the website.</p>
<p>Structured data is a good example. Imagine if Google's technology can directly understand the content on the web page and "structure" it in a few years. Then webmasters will not need to put structured data such as schema markup. However, the current situation is that Google is still far from perfect.</p>
<p>The two voices mentioned by Gary are actually understandable. I think that in the long run, SEO skills are still necessary to understand what information users need, how to search, and how to produce content. As for technical SEO, the correct mentality should be to help Google better understand the content of the website, rather than trying to exploit Google's shortcomings and trying to gain benefits from it.</p>
<p><strong>Information Retrieval<br/></strong>Gary mentioned it in a previous podcast<a href="./seo-newsletter-issue-32-33.html#toc-10">query parsing &amp; query understanding</a>, that is, when the user searches for a word, Google will expand it into more related words, and then search it in the index database; and this search action is the so-called information retrievel. A simple understanding is to determine whether a file contains certain information. This step uses<a href="./seo-newsletter-issue-27.html#toc-8">sign posting</a>Only by waiting for technology to improve efficiency can relevant results be found in the shortest time.</p>
<p>In information retrieval, when judging related words, an interesting little knowledge is - "buy car" and "sell car" are possible<a href="http://www.facebook.com/searchenginecommunity/posts/580626692675277">regarded as "synonyms"</a>", because when a user is searching for an item to "buy", even if the word "sell" is used on the web page, it is very consistent with the user's search intention.</p>
<p>The above steps only find all related web pages or files. This step gives each web page a rough score. Assuming that there are 1 billion related web pages for a search term, they will sort them and take the top 1,000 or so web pages. The results provided at this stage are actually quite good, but they are only ranking results based on some basic signals, and the entire ranking process is not completely over. These 1,000 web pages need to go through more signals and be reordered before they are the last search results that users see.</p>
