<h2 id="toc-4">[Technique] Scale judgment Redirect Mapping</h2>
<p>Redirect Mapping is an important step in website relocation. The purpose is to match the old URL with the new URL and set up a 301 redirect so that the traffic going to the old URL can be directed to the correct location. It is not difficult to create a Redirect Map when relocating a small or medium-sized website, or when the URL structure is the same. However, when the URL structure changes and the number of web pages is huge, it becomes a headache.</p>
<p>This article teaches two methods, which can effectively identify where the old URL should go when encountering the latter situation. The first one was introduced in the previous issue<a href="./seo-newsletter-issue-61.html#toc-8">Fuzzy Matching</a>, upload two strings of URLs, and determine which two URLs should be paired together based on the similarity of the URLs. The returned results are not always correct, so you still need to check whether the combination with a low Similarity Score is correct.</p>
<figure class="wp-block-image aligncenter size-large is-resized"><img alt="Illustration for SEO e-Newsletter Issue 62 – 2022.08.01~2022.08.15" class="wp-image-3808" decoding="async" height="198" loading="lazy" src="./wp-content/uploads/2022/08/image-9-1024x350.png" width="580"/><figcaption>Fuzzy Matching results</figcaption></figure>
<p>Another method is to first download the keywords that ranked before the website was moved, and then use Google to search<code><em>keyword site:www.newdomain.com</em></code>, judging from the SERP, which webpage Google ranks first, it may be the most relevant webpage. Finally, Python is used with a paid API to scale the above steps.</p>

<h2 id="toc-10">[Abstract] The mechanism behind URL "removal"</h2>
<figure class="embed embed--youtube"><div class="embed__frame"><iframe allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" allowfullscreen="" loading="lazy" referrerpolicy="strict-origin-when-cross-origin" src="https://www.youtube-nocookie.com/embed/DXPHyyOLv8Y" title="YouTube video player"></iframe></div><figcaption><a href="https://www.youtube.com/watch?v=DXPHyyOLv8Y" rel="noopener noreferrer">View original video on YouTube</a></figcaption></figure>
<p>This episode of the podcast returns to an earlier in-depth series where Gary explained how search engines work. It is not as simple as it seems on the surface for a search engine to "remove" a web page, because there are different mechanisms in the three stages of crawling, indexing, and serving, and their respective mechanisms may conflict with each other. For example, if disallow (<em>crawling stage</em>), and put noindex (<em>indexing stage</em>), then the "URL" of this web page may still be indexed.</p>
<p>There is no way to remove the URL during the Crawling stage. In addition, Gary specifically said that he believed that robots.txt should only be used in the crawling stage. A few years ago, Google decided to no longer support robots.txt.
This is also the reason for the<a href="https://searchengineland.com/google-to-stop-supporting-noindex-directive-in-robots-txt-319003">noindex</a>instruction.</p>
<p>Most of the real removal occurs in the indexing stage. Even when Google sees noindex in x-robots-tag or the URL itself is 404 in the crawling stage, the crawling stage only passes this information to the indexing stage to make decisions.</p>
<p>Removal in the serving stage refers to the URL removal tool in GSC. The URL here is not really removed from the index (index), but is only "hidden" in the search results, because removing the web page from the index will need to be synchronized to all data centers, and this process may even take several months.</p>
<p>The above summaries may seem simple, but in practice search engines may encounter very complex situations. For example, there are several URLs strung together with hreflang. Some of them are marked with noindex, but the rest are not. Since hreflang treats them as the same "document", all pages may not be included. For many extreme cases, Gary even said that he was not sure what would happen, but the only sure advice was to avoid such conflicting signals.</p>
