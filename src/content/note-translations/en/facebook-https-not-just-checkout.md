Websites don't only require HTTPS when they require users to enter a password or checkout.

HTTPS mainly protects Internet users from three parts.

1. **Encryption**: Prevent the data being transmitted from being read by others.
2. **Data Integrity**: Allow the recipient to detect whether the data has been tampered with during transmission.
3. **Verification**: Let the user know that they are connecting to the intended website server and not the person being impersonated.

If you only use HTTPS for login or transaction pages, other HTTP pages may still become entry points for attacks.

The attacker doesn't necessarily have to directly steal the account and password, but may also modify images, JavaScript, or page content, or make the user believe they are browsing the correct website.

This post was published in 2018 and also mentioned that Chrome would soon mark HTTP websites as unsafe.

I reserve it here as a historical note on website security concepts, rather than a how-to guide for today's browser interfaces.
